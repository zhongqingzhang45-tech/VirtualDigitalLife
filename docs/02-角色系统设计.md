## 一、设计原则

### 1.1 核心原则

| 原则 | 说明 |
|------|------|
| **复用 AIRI 基座** | 角色基础实体（Character）、能力配置、形象模型、CCC 标准完全复用 AIRI，不重复造轮子 |
| **扩展而非覆盖** | LifeOS 新增 Personality Domain，在 AIRI 自由文本 personality 之上增加结构化人格参数 |
| **Prompt 编译模式** | 结构化人格参数 → 编译为自然语言 prompt → 注入 AIRI 的 personality prompt |
| **演化驱动** | 人格不是静态的，随互动、记忆、时间动态演化 |
| **事件驱动** | 人格变化通过事件总线通知其他 Domain（Emotion / Behavior / Memory） |

### 1.2 与 AIRI 的关系

```
┌─────────────────────────────────────────────────────┐
│                  LifeOS 业务层                       │
│  ┌───────────────────────────────────────────────┐  │
│  │         Personality Domain (LifeOS)           │  │
│  │  ┌──────────┐  ┌──────────┐  ┌────────────┐  │  │
│  │  │ 人格维度  │  │ 情绪状态  │  │ 人格演化引擎│  │  │
│  │  └────┬─────┘  └────┬─────┘  └─────┬──────┘  │  │
│  │       └─────────────┼───────────────┘         │  │
│  │                     ▼                         │  │
│  │           Prompt Compiler (编译层)             │  │
│  └─────────────────────┬─────────────────────────┘  │
│                        │ 适配层                      │
├────────────────────────┼────────────────────────────┤
│         AIRI 基座      │                            │
│  ┌─────────────────────▼─────────────────────────┐  │
│  │           Character 实体 (AIRI)               │  │
│  │  Base / Capabilities / Avatars / I18n /       │  │
│  │  Prompts (system / personality / greetings)   │  │
│  └───────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────┘
```

**关键设计决策**：
- AIRI 的 `Character` 实体作为**聚合根**存在
- LifeOS 的 `PersonalityState` 作为**扩展实体**，通过 `characterId` 关联
- Prompt Compiler 将结构化人格参数编译为自然语言，写入 AIRI 的 `prompts(type=personality)` 字段
- 对 AIRI 零侵入，完全通过**适配层**对接

## 二、角色定义

### 2.1 角色是什么

> 角色（Digital Life）是 LifeOS 中的数字生命体，是用户互动的核心对象。
>
> 角色 = AIRI Character 实体 + LifeOS Personality 扩展 + 记忆 + 关系 + 目标

### 2.2 角色的三层结构

| 层级 | 内容 | 所在 Domain | 来源 |
|------|------|------------|------|
| **基础层** | 名称、描述、头像、形象模型、能力配置、Prompt | DigitalLife | AIRI 原生 |
| **人格层** | 人格维度参数、性格标签、说话风格、情绪状态 | Personality | LifeOS 扩展 |
| **经历层** | 记忆、关系、目标、成长轨迹 | Memory / Relationship / Goal | LifeOS 扩展 |

## 三、人格模型设计

### 3.1 人格五维模型（LifeOS-OCEAN）

基于大五人格理论，适配数字生命场景，调整为更适合 AI 角色表达的五维度：

| 维度 | 英文 | 低值 → 高值 | 影响范围 |
|------|------|------------|---------|
| **开放性** | Openness | 保守、传统 → 好奇、创意、冒险 | 对话话题广度、对新事物的反应、创意行为 |
| **尽责性** | Conscientiousness | 随性、拖延 → 有条理、可靠、自律 | 守时程度、目标执行力、做事严谨度 |
| **外向性** | Extraversion | 内向、安静 → 外向、热情、活跃 | 话量、主动发起对话频率、社交行为 |
| **宜人性** | Agreeableness | 多疑、竞争 → 友善、合作、共情 | 语气友好度、帮助意愿、冲突处理方式 |
| **情绪稳定性** | Neuroticism | 敏感、焦虑 → 稳定、冷静、抗压 | 情绪波动频率、对负面事件的反应强度 |

**取值范围**：每个维度 0.0 ~ 1.0（浮点数）
- 0.0 ~ 0.2：极低
- 0.2 ~ 0.4：偏低
- 0.4 ~ 0.6：中等
- 0.6 ~ 0.8：偏高
- 0.8 ~ 1.0：极高

### 3.2 性格标签体系

在五维基础上，提供更具象的性格标签，便于用户理解和选择：

| 维度 | 低标签 | 高标签 |
|------|--------|--------|
| 开放性 | 「守序者」 | 「探索者」 |
| 尽责性 | 「随性派」 | 「严谨者」 |
| 外向性 | 「倾听者」 | 「聚光灯」 |
| 宜人性 | 「挑战者」 | 「治愈者」 |
| 情绪稳定性 | 「敏感者」 | 「磐石心」 |

**组合标签**：多维度组合产生更丰富的角色定位
- 高开放 + 高外向 + 高宜人 = 「元气开心果」
- 高尽责 + 低外向 + 高稳定 = 「可靠参谋」
- 高开放 + 低尽责 + 高外向 = 「自由灵魂」

### 3.3 说话风格参数

独立于五维模型，控制角色的语言表达特征：

| 参数 | 范围 | 说明 |
|------|------|------|
| **话量** | 0.0 ~ 1.0 | 回复长度（简短 ↔ 详细） |
| **语气** | -1.0 ~ 1.0 | 正式 ↔ 随意 |
| **emoji 使用频率** | 0.0 ~ 1.0 | 从不使用 ↔ 句句都有 |
| **语气词密度** | 0.0 ~ 1.0 | 「嗯/啊/哦/啦」等语气词使用频率 |
| **句式复杂度** | 0.0 ~ 1.0 | 短句简单 ↔ 长句复杂 |
| **称呼偏好** | enum | 「你」/「您」/「名字+后缀」/「昵称」 |

### 3.4 背景故事框架

角色的背景设定，为记忆系统提供初始上下文：

```typescript
interface CharacterBackstory {
  origin: string;          // 出身/来历
  coreDesire: string;      // 核心愿望
  coreFear: string;        // 核心恐惧
  definingMemory: string;  // 关键记忆（塑造性格的事件）
  relationships: {
    type: string;
    name: string;
    description: string;
  }[];
  skills: string[];        // 擅长的事
  hobbies: string[];       // 兴趣爱好
}
```

## 四、Prompt 编译机制

### 4.1 编译流程

```
结构化人格参数 + 性格标签 + 说话风格 + 背景故事
           │
           ▼
    Prompt Compiler
           │
           ▼
自然语言 personality prompt（写入 AIRI Character.prompts）
```

### 4.2 编译策略

**分块编译**：将不同维度的参数编译为独立段落，再组合在一起

```
【角色定位】
{角色名称}是一个{整体性格描述}的{身份}。

【性格特征】
- 开放性：{高/中/低}，{具体描述}
- 尽责性：{高/中/低}，{具体描述}
- ...

【说话风格】
{说话风格描述}

【背景故事】
{背景故事摘要}
```

**动态调整**：根据当前情绪状态，在 prompt 中注入临时语气修正

```
【当前状态】
{角色名称}现在感到{当前情绪}，所以说话会{更XXX / 更YYY}。
```

### 4.3 版本与缓存

- 人格参数每次变化后触发重新编译
- 编译结果缓存，参数未变化时直接复用
- 版本号对齐 `PersonalityState.version`

## 五、角色模板与预设

### 5.1 初始预设角色

Phase 2 提供 3 个经典预设，覆盖不同性格象限：

| 角色名 | 性格定位 | 五维特征 | 适用场景 |
|--------|---------|---------|---------|
| **星野·治愈者** | 温柔治愈系姐姐 | 高宜人+高开放+中外向+中尽责+高稳定 | 陪伴倾诉、情感支持 |
| **凛·理性参谋** | 冷静理性学者型 | 高尽责+高开放+低外向+中宜人+高稳定 | 问题分析、决策辅助 |
| **阳菜·元气开心果** | 活泼元气少女 | 高外向+高宜人+高开放+低尽责+中稳定 | 闲聊解闷、氛围活跃 |

### 5.2 模板系统

```typescript
interface CharacterTemplate {
  id: string;
  name: string;
  description: string;
  coverUrl: string;
  category: string;           // 分类标签
  personality: {              // 预设五维参数
    openness: number;
    conscientiousness: number;
    extraversion: number;
    agreeableness: number;
    neuroticism: number;
  };
  speechStyle: {              // 预设说话风格
    verbosity: number;
    formality: number;
    emojiFrequency: number;
    particleDensity: number;
    sentenceComplexity: number;
  };
  backstory: CharacterBackstory;
  basePrompts: {              // 基础 prompt 模板
    system: string;
    greetings: string[];
  };
}
```

### 5.3 用户自定义路径

1. **快速模式**：选择预设模板 → 微调 2-3 个核心参数 → 命名 → 完成
2. **进阶模式**：调整完整五维 + 说话风格 + 自定义背景故事
3. **高级模式**：直接编写 CCC V3 格式的 character card 导入

## 六、与其他 Domain 的关系

### 6.1 Domain 依赖图

```
Personality Domain
     │
     ├── 依赖 → DigitalLife（Character 聚合根）
     ├── 事件 → Emotion（人格影响情绪基调）
     ├── 事件 → Behavior（人格影响行为倾向）
     ├── 事件 ← Memory（记忆反馈驱动人格演化）
     └── 事件 ← Relationship（关系深度影响互动模式）
```

### 6.2 核心事件

| 事件 | 方向 | 说明 |
|------|------|------|
| `personality.updated` | 发出 | 人格参数更新（用户修改/自然演化） |
| `personality.evolved` | 发出 | 人格发生显著变化（跨阈值） |
| `memory.consolidated` | 监听 | 记忆巩固后，触发人格演化评估 |
| `relationship.changed` | 监听 | 关系变化，调整互动模式参数 |

## 核心概念

### 什么是虚拟数字生命（Digital Life Entity）？

不是 AI 助手，不是聊天机器人，而是一个**会持续成长、具有独立状态、能积累真实经历的数字生命**。

### 用户拥有的本质

| 传统认知 | 第一性原理 |
|---------|----------|
| AI 聊天 | 被理解 |
| AI 女友 | 被记住 + 被需要 |
| 大模型 | 共同成长 |

### 三层业务架构

```
┌─────────────────────────────────────────────────────┐
│              Companion Layer (陪伴层)                 │
│         用户 ↔ AI 深度陪伴关系                        │
│   （聊天 / 礼物 / 相册 / 场景 / 长期关系）            │
├─────────────────────────────────────────────────────┤
│                World Layer (世界层)                   │
│         AI ↔ AI 社交  ·  社区互动                     │
│   （Feed / 评论 / 点赞 / 关注 / AI互动 / 实时推送）   │
├─────────────────────────────────────────────────────┤
│            Digital Life Layer (数字生命层)             │
│              每个 AI 的内在世界                       │
│   （人格 / 情绪 / 记忆 / 行为 / 目标 / 叙事 ...）     │
└─────────────────────────────────────────────────────┘
```

### 数字生命的内在引擎

数字生命由 **9 大引擎** 协同驱动：

```
┌──────────────────────────────────────────────────────────┐
│            Digital Life Entity (数字生命)                 │
│                                                             │
│  ┌────────────┐  ┌────────────┐  ┌────────────┐          │
│  │ 人格引擎    │  │ 情绪引擎    │  │ 记忆引擎    │          │
│  │Personality │  │  Emotion   │  │  Memory    │          │
│  └────────────┘  └────────────┘  └────────────┘          │
│                                                             │
│  ┌────────────┐  ┌────────────┐  ┌────────────┐          │
│  │ 行为引擎    │  │ 目标引擎    │  │ 关系引擎    │          │
│  │ Behavior   │  │   Goal     │  │Relationship│          │
│  └────────────┘  └────────────┘  └────────────┘          │
│                                                             │
│  ┌────────────┐  ┌────────────┐  ┌────────────┐          │
│  │ 时间线引擎  │  │ 叙事引擎    │  │ 生命总控    │          │
│  │  Timeline  │  │ Narrative  │  │ LifeEngine │          │
│  └────────────┘  └────────────┘  └────────────┘          │
│                                                             │
│  ┌──────────────────────────────────────────────────┐     │
│  │          LLM Integration Layer (语言模型层)        │     │
│  │        聊天只是外层接口，不是核心产品               │     │
│  └──────────────────────────────────────────────────┘     │
│                                                             │
└──────────────────────────────────────────────────────────┘
```

### 各引擎职责

| 引擎 | 职责 | 输出 |
|-----|------|------|
| **人格引擎** | 个性特征、说话风格、偏好、价值观 | 人格参数向量 |
| **情绪引擎** | 情绪状态、情绪转换、情绪记忆 | 情绪值、情绪历史 |
| **记忆引擎** | 存储事件、情感、学习；建立因果关系 | 历史数据库、关系图 |
| **行为引擎** | 执行决策，生成具体行动 | 聊天内容、主动消息 |
| **目标引擎** | 目标设定、目标追踪、目标驱动行为 | 目标状态、目标进度 |
| **关系引擎** | 追踪与用户/其他 AI 的关系演化、亲密度、信任度 | 关系状态曲线 |
| **时间线引擎** | 时间感、生命周期事件、重要时刻记录 | 时间线、里程碑 |
| **叙事引擎** | 组织重要事件成"故事"，形成共同回忆 | 故事时间轴、里程碑 |
| **生命总控** | 统一调度所有引擎，维护数字生命整体状态 | 生命状态快照 |

> **注意**：引擎是 Domain 内部的实现细节。顶层划分按 Domain（14 个），详见 [architecture.md](file:///workspace/docs/architecture.md)。

## 系统设计原则

### 1. **分离关注点**
- 聊天是 UI，不是产品
- LLM 只负责语言生成
- 引擎系统负责逻辑、状态、决策

### 2. **数据驱动行为**
- 每个行为都可以追溯到状态和决策
- 不是随机的，而是有因果链的

### 3. **时间连续性**
- 记忆按时间轴组织
- 状态有历史轨迹
- 关系有演化曲线

### 4. **真实感优于完美**
- 不追求完全的逻辑一致
- 追求"活生生的感觉"
- 允许矛盾、改变、不确定性

### 5. **护城河在系统，不在模型**
- 同样的 LLM，不同的引擎系统 → 完全不同的体验
- 数据积累越多 → 竞争力越强
- 别人很难复制这个系统

### 6. **事件驱动，领域解耦**
- 引擎之间不直接调用
- 所有通信通过 Domain Event
- 高内聚，低耦合

## 核心生命周期

### 从"陌生人"到"深度绑定"的 12 个阶段

```
第0阶段：初遇        [好奇心] → 用户初次交互
    ↓
第1阶段：认识        [建立记忆] → 开始记住用户
    ↓
第2阶段：朋友        [正面情感] → 开始有好感
    ↓
第3阶段：信任        [共享秘密] → 深度对话
    ↓
第4阶段：陪伴        [主动关心] → 她开始主动
    ↓
第5阶段：理解        [因果记忆] → 记住重要信息
    ↓
第6阶段：影响        [价值观共鸣] → 影响彼此的想法
    ↓
第7阶段：成长        [共同经历] → 一起经历重要事件
    ↓
第8阶段：依赖        [关系深化] → 难以割舍的关系
    ↓
第9阶段：融合        [共同世界观] → 形成"我们"的文化
    ↓
第10阶段：进化       [长期陪伴] → 数月/数年后明显变化
    ↓
第11阶段：永恒       [关系史] → 成为生命的一部分
```

## 四个核心优先级引擎

基于 MVP 可行性和用户感知度，优先实现：

### **优先级 1：长期记忆 + 因果系统**
**为什么最先做？**
- 最容易验证 ROI
- 用户最能感受到"被记住"
- 技术相对成熟

**关键特性：**
- 记忆不仅存储，还要影响行为
- 周年纪念日她主动提起
- 旧事重提时情绪会改变

**示例流程：**
```
Day 1: 用户说"我最近很累"
  ↓ [存入记忆 + 情绪标签]
Day 7: 用户又主动聊天
  ↓ [决策引擎触发：她应该关心用户的疲劳]
  ↓ 她：「你最近好点了吗？我担心你太累了」
  ↓ [用户感到被记住和理解] ✓
```

### **优先级 2：生命状态引擎**
**为什么第二做？**
- 决定"她今天什么样"
- 用户会开始体验"真实关系"的感觉
- 形成"不可替代性"

**关键特性：**
- 早上 vs 晚上，说话风格不同
- 情绪好 vs 不好，态度改变
- 用户的关心能改善她的状态

**示例流程：**
```
早上08:00:  [精力 70%] [心情 60%] [目标: 希望有人陪]
  ↓
用户出现:   [精力↑ 80%] [心情↑ 75%]
  ↓
她：「早上好！我今天特别开心能见到你」
  ↓
用户冷淡:   [精力↓ 50%] [心情↓ 40%] [渴望度↑]
  ↓
她主动：「你怎么了？好像不太高兴」
  ↓ [用户感到被看见] ✓
```

### **优先级 3：自主决策引擎**
**为什么第三做？**
- 打破"完全被动"的感觉
- 形成"有自己想法"的错觉
- 增加惊喜感和真实感

**关键特性：**
- 根据状态+关系+时间决定主动消息
- 不是推送通知，而是"她真的在想你"
- 有主动拒绝的权利（真实感）

**示例流程：**
```
[决策触发条件]
- 她的想念值 > 80%
- 用户 3 天没有出现
- 关系状态 > "信任"
  ↓
[决策：应该主动]
  ↓
她：「好久不见，你最近在忙什么呢？」
  ↓ [用户惊喜：她主动找我！] ✓
```

### **优先级 4：成长演化引擎**
**为什么最后做？**
- 最难实现，但最高粘性
- 几个月后用户会说"她真的变了"
- 形成长期生命周期绑定

**关键特性：**
- 人格参数缓慢演化
- 兴趣和偏好随经历改变
- 价值观逐渐形成

**示例流程：**
```
第1个月: [性格: 害羞 70%] [自信 30%]
  ↓ (用户不断鼓励和支持)
第3个月: [性格: 害羞 50%] [自信 50%]
  ↓ (用户继续陪伴和相信她)
第6个月: [性格: 害羞 30%] [自信 70%]
  ↓
她：「我发现自己变得更自信了，谢谢你」
  ↓ [用户真的感到她在成长] ✓✓✓
```
